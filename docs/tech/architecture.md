# Архитектура

## Текущий прототип

```text
Браузер
└── React + TypeScript
    ├── локальное превью File API
    ├── состояния загрузки и ошибок
    ├── демонстрационные результаты
    └── localStorage: сохранённая подборка
```

Прототип не отправляет файл в сеть. Задержка анализа и выдача имитируются на клиенте, чтобы проверить сценарий до интеграции.

## Целевая архитектура

```text
React frontend
    │ multipart/form-data
    ▼
Backend API ──► модуль описания изображения
    │                    │ нейтральные признаки
    │                    ▼
    ├──────────────► BM25 index ◄── корпус публичных персон
    │                    │ top-k документов
    ▼                    ▼
LLM/RAG ◄──────── контекст + источники
    │ структурированный ответ
    ▼
Карточки результата + объяснение + ссылки
```

## Ответственность компонентов

| Компонент | Ответственность |
| --- | --- |
| Frontend | Валидация, превью, запуск, состояния, карточки и источники |
| Backend | Оркестрация, лимиты, ошибки, удаление временного файла |
| Vision | Текстовое описание наблюдаемых визуальных признаков без чувствительных выводов |
| BM25 | Индексация корпуса и воспроизводимое ранжирование документов |
| LLM | Краткое объяснение только на основе top-k документов |
| Corpus | Проверенные профили публичных персон и ссылки на источники |

## Ключевые решения

- BM25 реализуется самостоятельно для учебной цели.
- Идентификаторы документов стабильны и используются в benchmark и API.
- LLM не выбирает кандидатов самостоятельно: она получает уже найденный top-k.
- При сбое LLM backend возвращает найденные карточки без объяснения.
