# Данные, поиск и качество

## Документ корпуса

```json
{
  "id": "person_0042",
  "name": "Имя персоны",
  "occupation": ["актёр"],
  "visualDescription": "...",
  "aliases": ["..."],
  "sourceUrl": "https://...",
  "sourceTitle": "...",
  "checkedAt": "2026-10-16"
}
```

В индекс попадают имя, профессия и нейтральное визуальное описание. Контакты, адреса, биометрические шаблоны, сведения о здоровье, этническом происхождении и частных лиц не собираются.

## BM25

Перед индексированием текст нормализуется: нижний регистр, токенизация, удаление пунктуации, стоп-слова и лемматизация. Реализация хранит document frequency, длину документа и среднюю длину корпуса. Параметры `k1` и `b` фиксируются в конфигурации эксперимента.

## Размеченный набор

- не менее 10 текстовых описаний-запросов;
- минимум 3 релевантных документа для каждого запроса;
- отдельные случаи: причёска, форма лица, аксессуары, слабое описание, отсутствие совпадений;
- разметка хранит ID документов, а не только имена.

## Метрики

- `Recall@5` — доля релевантных документов, попавших в первые пять результатов;
- `MRR` — среднее обратное место первого релевантного результата;
- дополнительно фиксируются пустая выдача и latency.

Результаты сравниваются с простой baseline-моделью по числу общих токенов. Ошибки группируются: описание изображения, словарь, индекс, ранжирование и неверная разметка.

## Безопасность

Проект ищет визуальные референсы, не идентичность. В интерфейсе и документации нельзя утверждать, что найденный человек «тот же самый», родственник или имеет определённые чувствительные характеристики.
